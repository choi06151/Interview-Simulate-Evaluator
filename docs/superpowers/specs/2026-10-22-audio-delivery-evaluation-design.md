# 음성 전달 평가 기능 설계

- 상태: 검토 대기
- 작성일: 2026-10-22
- 대상 프로젝트: 게임 엔진 클라이언트 프로그래머 면접 평가
- 관련 기준: 텍스트 질문 단위 v2.0, 최종 점수 50:50 평균

## 1. 목표

면접 녹음에서 지원자 발화를 면접관 발화와 구분하고, 말하기 전달 특성에 대한 근거를 만들어 음성 점수와 별도 리뷰를 지원한다. 텍스트 점수는 답변의 기술적·상황적 내용만 평가하고, 음성 점수는 말의 전달 방식만 평가한다. 두 점수를 모두 계산할 수 있을 때 최종 총점은 두 정수 점수의 산술 평균을 반올림한다.

## 2. 사용자 요구와 확정 제약

- 텍스트 평가는 대답의 내용과 정확성에 집중한다.
- 음성 평가는 호흡/쉼, 말하기 속도 등 녹음에서 드러나는 전달 특성에 집중한다.
- 텍스트와 음성의 점수는 별도로 보여 주고, 최종 총점은 50:50 평균으로 유지한다.
- 음성 파일과 산출물은 기본적으로 로컬에서 처리하고 저장한다.
- 한 번의 평가로 성격·감정·자신감·채용 적합성을 추론하지 않는다.
- 자동 측정은 근거이지 보편적인 정상 범위나 점수 그 자체가 아니다.

## 3. 용어와 점수 범위

- **텍스트 점수:** 질문별 답변 내용 점수의 단순 평균. 기술 정확성, 논리, 사례, 적용/검증을 평가한다. 발화 속도·호흡·음량·억양은 반영하지 않는다.
- **음성 점수:** 아래 전달 항목의 점수를 합한 100점. 기술 정답 여부는 반영하지 않는다.
- **최종 총점:** `round_half_up((텍스트 점수 + 음성 점수) / 2)`. 후보자 음성 구간을 특정할 수 없거나 평가 근거가 부족하면 음성과 총점은 산출 보류한다.
- **호흡/쉼:** 자동 측정으로는 문장·발화 사이 침묵 길이와 분포를 기록한다. 호흡 소리 검출은 탐지 후보로만 취급한다. 실제 호흡 습관을 단정하지 않는다.

## 4. 음성 점수 루브릭 v2.0 제안

| 항목 | 배점 | 평가 기준 | 자동 분석 증거 |
|---|---:|---|---|
| 이해 가능성 | 30 | 실제 들었을 때 핵심 발화를 따라갈 수 있는가. 억양/발음 차이 자체가 아니라 의미 전달을 막는 구간을 본다. | ASR 누락·불일치·신뢰도는 보조 신호만 제공. 최종 청취 판단이 없으면 잠정/평가 보류 |
| 말하기 속도와 안정성 | 20 | 지원자 발화 구간의 속도 및 구간 간 변화가 이해를 방해하는가. 보편적인 이상 속도 기준을 두지 않는다. | 후보자 전용 음절/문자 속도, 구간별 분포와 변화 |
| 호흡·쉼·비유창성 | 20 | 불필요하게 긴 쉼, 문장 호흡 배치, 반복/말막힘이 의미 전달을 반복적으로 끊는가. 잠깐 생각하는 쉼은 감점 사유가 아니다. | 후보자 발화 안의 쉼 길이/빈도, ASR 반복·필러 후보, 선택적 비언어 호흡 후보 |
| 음량과 신호 안정성 | 15 | 녹음 조건을 고려했을 때 말소리가 안정적으로 들리며 갑작스러운 크기 변화/클리핑이 전달을 방해하는가. | 상대 RMS/dBFS 분포, clipping 비율, 잡음 추정. 장비/거리 영향 고려 |
| 억양·강세·운율 | 15 | 문장 경계와 중요한 낱말을 청자가 구별할 수 있게 운율을 사용하는가. 특정 억양·음색·성별·감정 인상은 평가하지 않는다. | 유성 구간 F0 contour, 범위/변화량, 강도 envelope. 수치만으로 점수 확정 금지 |

각 항목은 관찰 구간과 근거를 기록한다. 발화 시간, pitch, RMS의 보편 점수 임계값은 두지 않는다. 모델·기기 차이에 따라 변하므로 우선 본인 발화 내 비교와 청취 관찰을 사용한다. 음성 항목별 근거를 확인할 수 없으면 임의 점수를 만들지 않는다.

## 5. 처리 흐름

1. M4A 등 입력 음성을 PyAV/FFmpeg 계열로 PCM 분석 입력으로 변환한다. 원본은 보존한다.
2. 기존 faster-whisper 전사/단어 타임스탬프를 생성한다.
3. 화자 분리기로 시간 구간을 `SPEAKER_00` 등으로 할당한다. 초기안은 pyannote.audio의 커뮤니티 diarization 모델을 사용한다. 녹음에서 예상 화자 수를 알면 설정값으로 전달한다.
4. 각 ASR 구간을 시간 중첩으로 화자 구간과 연결한다. 사용자 전사에 참석자 표기가 있으면 후보자/면접관과 diarization 라벨 매핑을 돕는다. 자동 매핑이 모호하면 `--candidate-speaker` 수동 선택을 지원한다.
5. 후보자 화자 구간만 대상으로 말하기 속도, 구간 내 쉼, 상대 음량/클리핑, F0/강도 envelope를 측정한다. 질문별 지표 연결이 불확실하면 전체 면접 단위 지표로만 저장한다.
6. JSON 증거 보고서에 입력 파일, 모델/버전, 매핑 방법, 측정값, 미지원 항목, 제한사항과 분석 신뢰도를 저장한다.
7. 평가 출력은 텍스트 평가와 음성 평가를 독립 작성하고, 두 점수가 모두 유효하면 총점을 산출한다. 사람의 청취 판단과 자동 측정 사실을 분리해 기술한다.

## 6. 구성요소와 변경 범위

- `scripts/analyze_voice.py`: 기존 ASR evidence 생성기를 확장하거나 역할별 분석 모듈과 연결한다.
- `scripts/`의 음성 지표 모듈: 발화 구간 매핑, 속도/쉼/RMS/F0 산출과 신뢰도 검증을 담당한다.
- `requirements-audio.txt`: diarization 및 signal feature 의존성을 선택 가능한 오디오 extra로 추가한다. 설치 크기와 CPU/GPU 호환성을 문서화한다.
- `references/voice-scoring-rubric.md`: v2.0 배점 및 청취/자동증거 경계를 정의한다.
- `references/audio-analysis-workflow.md`: 설치, 토큰, 실행, 수동 화자 매핑, 결과 검토 과정을 안내한다.
- `references/output-format.md`, `records/templates/evaluation-template.md`, `SKILL.md`: 텍스트/음성 분리, 점수 평균, 낮은 신뢰도/산출 보류 형식을 동기화한다.
- 기존 세션 평가와 음성 점수는 소급 변경하지 않는다. 사용자가 별도 요청하지 않는 한 새 기준은 적용 시점 이후 회차에 사용한다.

## 7. 의존성·보안·오류 처리

- pyannote 커뮤니티 모델은 모델 저장소 약관 동의와 Hugging Face 읽기 토큰이 필요할 수 있다. 토큰은 환경 변수에서 읽고 코드/JSON/로그/기록에 절대로 저장하지 않는다. 최초 모델 다운로드 뒤에는 모델 파일을 로컬 캐시에서 추론한다.
- 네트워크/토큰/모델 접근이 안 되면 ASR 및 신호 기능과 화자 수동 매핑을 사용할 수 있게 하고, 자동 화자 분리는 `사용 불가`로 보고한다. 지원자 발화 구간이 확보되지 않으면 후보자 음성점수와 최종점수를 보류한다.
- diarization은 화자 정체성을 알지 못하고 라벨만 분리한다. 화자 중첩, 짧은 응답, 유사한 음색, 잡음은 오류 원인이므로 transcript speaker label 또는 사람 확인을 통해 역할을 연결한다.
- 소음/에코/클리핑/채널 손상은 참가자 전달 결함으로 오인하지 않는다. 조건이 불충분한 항목은 `평가 불가`로 남긴다.
- 음성 특징을 감정/성격/건강/억양 출신 추론에 사용하지 않는다.

## 8. 기록 형식

`voice-evidence.json`은 다음을 포함한다.

- schema 버전, 원본 경로 및 duration, 사용 모델/버전
- speaker turns, candidate speaker ID와 매핑 근거/신뢰도
- 후보자 전용 발화 구간과 선택적 질문 연결
- 총 발화 시간, 구간별 속도, 휴지 통계, RMS/dBFS 분포, clipping, F0 contour 통계
- 수동 검토 필요 항목, 실패/미지원 원인, 데이터 해석 제한

`evaluation.md`는 기존 형식을 확장한다.

- 텍스트 질문별 점수 표 및 텍스트 평균
- 별도 음성 점수 표와 `음성 평가 리뷰`
- 직접 청취 여부 및 자동 증거 신뢰도
- 텍스트/음성 점수와 최종 50:50 평균

## 9. 완료 조건

- 면접관과 후보자가 번갈아 말하는 예시 음성에서 구간별 화자 라벨을 산출하고, 수동 매핑으로 후보자 구간만 선택할 수 있다.
- 후보자 전용 속도/쉼/RMS/F0 통계가 출력되고 전체 화자 혼합값과 구분된다.
- ASR/diarization 오류 또는 역할 미확정 시 후보자 개인 음성 점수를 조용히 산출하지 않고 보류 사유를 남긴다.
- 텍스트 평가에 호흡·속도·음향 지표가 섞이지 않고, 음성 점수에는 답변의 기술적 정답률이 섞이지 않는다.
- 출력 합계와 최종 평균이 지정 공식과 일치한다.
- 원본 음성은 변경/외부 업로드 없이 로컬 처리 경로를 제공한다.

## 10. 열린 설계 사항

- 특정 면접 녹음에 맞는 diarization의 화자 구간 오류율은 모델 실행 후 표본을 청취 대조해야 한다.
- 호흡 소리 자동 분류는 기본 점수에 넣지 않고 1차 버전에서는 쉼/호흡 간격 지표 및 청취 코멘트로 한정한다. 신뢰 가능한 모델을 찾기 전 호흡 횟수를 기계적으로 감점하지 않는다.
- `librosa.pyin` 또는 Praat/Parselmouth 중 구현 의존성은 구현 계획에서 기존 Python/CPU 환경과 호환성을 확인해 결정한다.
- 현재 실행 환경에서 사용자 파일을 모델이 직접 청취해 점수화하는 기능은 포함되지 않는다. 이번 범위는 로컬 음향 지표와 화자 전용 증거를 생성하고, 평가자가 근거 기반 리뷰를 쓰게 하는 것이다.
