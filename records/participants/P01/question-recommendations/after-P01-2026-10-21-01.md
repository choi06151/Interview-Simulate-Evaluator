## 1. 종류별 오브젝트 풀 설계

- 연결 평가: Q2·Q3 — Queue 사용과 Dictionary 비교 (60/100, 40/100)
- 난이도: 중
- 질문: 총알, 적 종류 3개, 아이템을 각각 재사용하는 오브젝트 풀을 설계한다면 자료구조를 어떻게 조합하고 각 구조의 역할은 무엇인가요?
- 후속 질문:
  - 풀에서 객체를 꺼낼 때와 반환할 때 어떤 상태를 초기화합니까?
  - 해당 종류의 비활성 객체가 없으면 어떻게 합니까?
  - Dictionary가 사라져도 되는 구조인가요? 풀 내부 대기열은 어떤 역할인가요?
- 좋은 답변 신호: 타입/키 기반 풀 조회와 풀 내부 재사용 순서를 구분하고, 생성·반환·초기화·최대 용량 정책을 설명함.

## 2. 풀링의 비용과 GC 측정

- 연결 평가: Q1 — 스택/힙, 할당·해제, 풀링 (60/100)
- 난이도: 중
- 질문: 총알 100개를 발사할 때마다 Instantiate/Destroy하는 구현에서 GC 또는 프레임 문제가 의심됩니다. 무엇을 측정하고 풀링 효과를 어떻게 검증하겠습니까?
- 후속 질문:
  - 관리 힙 할당량과 native 메모리 사용량을 어떻게 구분합니까?
  - 풀 크기를 지나치게 키웠을 때의 비용은 무엇인가요?
  - 할당은 줄었는데 프레임 시간이 개선되지 않았다면 다음에 무엇을 확인합니까?
- 좋은 답변 신호: Profiler의 할당/GC/CPU 지표로 병목을 확인하고 동일 조건의 전후 비교를 하며 풀의 메모리 점유도 고려함.

## 3. 내부·외부 단편화 구분

- 연결 평가: Q5 — 페이징/세그멘테이션과 메모리 단편화 (20/100)
- 난이도: 중
- 질문: 내부 단편화와 외부 단편화를 블록 예시로 설명하고, 페이징과 세그멘테이션에서 어떤 문제가 발생할 수 있는지 설명해 주세요.
- 후속 질문:
  - 페이징은 외부 단편화를 왜 줄일 수 있나요?
  - 페이지 크기보다 작은 남은 공간은 어떤 단편화인가요?
  - 가변 크기 세그먼트를 배치할 때 빈 공간이 나뉘어 남는 이유는 무엇인가요?
- 좋은 답변 신호: 단편화가 할당 블록 내부에 남는 공간인지, 할당 사이에 흩어진 빈 공간인지 정확히 구분하고 각 방식과 연결함.

## 4. C# Delegate와 Event 권한 차이

- 연결 평가: Q6 — Delegate와 Event (30/100)
- 난이도: 중
- 질문: Delegate 필드와 `event`를 사용한 이벤트 선언을 비교하고, 구독자와 선언 클래스가 각각 할 수 있는 일을 설명해 주세요.
- 후속 질문:
  - 선언 클래스 밖에서 `event`를 직접 호출할 수 있나요?
  - 구독 해제를 놓치면 어떤 문제가 생길 수 있나요?
  - 적 사망을 UI에 알리는 상황에서 이벤트 인자를 어떻게 설계하겠습니까?
- 좋은 답변 신호: Delegate의 호출 가능한 메서드 참조 성격과 Event의 구독 인터페이스/발생 권한 제한을 코드 수준에서 설명함.

## 5. Canvas 분리 최적화 검증

- 연결 평가: Q4 — 정적/동적 Canvas 분리 경험 (60/100)
- 난이도: 중
- 질문: 매초 바뀌는 HP UI와 고정된 인벤토리 장식을 별도 Canvas로 분리했다고 가정합시다. 어떤 비용을 줄일 것으로 기대하고 실제 효과를 어떻게 측정하겠습니까?
- 후속 질문:
  - 동적 요소를 한 Canvas에 모을 때의 장점과 단점은 무엇입니까?
  - Canvas를 너무 많이 나누면 어떤 비용이 생길 수 있나요?
  - UI가 바뀌어도 실제 병목이 Canvas rebuild가 아니라면 어떻게 판단합니까?
- 좋은 답변 신호: 배칭/메시 재생성 및 Canvas 변경 영향 범위를 이해하고, Profiler로 실제 병목과 전후 비용을 확인함.
