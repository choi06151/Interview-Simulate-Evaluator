# 최재원 5회차 이후 개인별 추천 질문

- 참가자: 최재원 (P01)
- 기준 세션: [P01-2026-10-27-01](../sessions/P01-2026-10-27-01/evaluation.md)
- 기준 루브릭: 텍스트 v2.0
- 목적: Flyweight와 pooling 분리, C# 이벤트 의미, HFSM 계층 구조를 적용 상황에서 검증

## 1. Flyweight와 Object Pool 분리

- 연결 평가: Q1 — Flyweight / Object Pooling (45/100)
- 난이도: 중
- 질문: 수천 개의 총알이 같은 메시·머티리얼·기본 대미지를 공유하지만 위치·속도·남은 수명은 다를 때 어떤 데이터를 공유하고 어떤 데이터는 인스턴스별로 둘까요?
- 후속 질문:
  - Flyweight가 줄이는 비용과 Object Pool이 줄이는 비용은 각각 무엇인가요?
  - 강화 총알처럼 일부 대미지가 달라지면 공유 데이터와 개별 상태를 어떻게 나누나요?
  - 풀에서 총알을 꺼낼 때 이전 사용자의 속도·수명·이벤트 구독을 어떻게 초기화하나요?
- 좋은 답변 신호: intrinsic/extrinsic state를 구분하고 메모리 중복과 생성·파괴 비용을 혼동하지 않으며, 풀 재사용 초기화 절차를 설명함.

## 2. Action, event, UnityEvent 및 구독 수명

- 연결 평가: Q2 — 옵저버와 이벤트 (55/100)
- 난이도: 중
- 질문: 체력이 바뀔 때 UI와 사운드가 반응하도록 `Action`, C# `event`, `UnityEvent`를 각각 적용한다면 발행 권한과 Inspector 연결에서 어떤 차이가 있나요?
- 후속 질문:
  - 외부 클래스가 이벤트를 직접 호출할 수 없는 이유는 무엇인가요?
  - `OnEnable`에서 구독하고 `OnDisable`에서 해제하는 예를 들어 주세요.
  - 구독 해제가 빠졌을 때 씬 전환/오브젝트 파괴 후 어떤 문제가 생기며 어떻게 검증하나요?
- 좋은 답변 신호: 모두 delegate/event 구조와 연결되는 방식을 정확히 구분하고 발행 권한, 직렬화/Inspector 편집, 생명주기 안전성을 설명함.

## 3. 상태 패턴과 HFSM의 계층 전이

- 연결 평가: Q4 — FSM/State/HFSM (50/100)
- 난이도: 중상
- 질문: 캐릭터 AI에 `Grounded`와 `Airborne` 상위 상태가 있고 각각 `Idle`/`Run`, `Jump`/`Fall` 하위 상태가 있을 때 HFSM의 상태 구조와 전이를 설명해 주세요.
- 후속 질문:
  - 상위 상태의 공통 동작과 하위 상태의 진입/종료 동작을 어떻게 나누나요?
  - HFSM과 Behavior Tree가 해결하려는 문제는 어떻게 다른가요?
  - FSM 모델과 State 패턴 구현은 같은 개념인가요?
- 좋은 답변 신호: 계층 상태와 상위 전이/공통 동작을 설명하고, FSM 모델과 구현 패턴 및 Behavior Tree를 구분함.

## 4. 상속과 조합 가능한 이동 능력

- 연결 평가: Q3 — 컴포넌트 기반 설계와 상속 (65/100)
- 난이도: 중
- 질문: 걷기·비행·수영 능력을 여러 몬스터가 서로 다르게 조합해야 할 때 공통 생명주기, 이동 기능, 공격 기능을 상속과 컴포넌트로 어떻게 나누겠습니까?
- 후속 질문:
  - 새 능력을 가진 몬스터를 추가할 때 기존 코드 변경을 어떻게 줄이나요?
  - 컴포넌트 간 의존성을 어떤 인터페이스나 데이터로 관리하나요?
  - 상속이 더 단순하고 적절한 경우는 어떤 조건인가요?
- 좋은 답변 신호: 안정적인 공통 is-a 규칙과 조합 가능한 기능을 분리하고, 확장 시 변경 범위와 의존성/테스트 기준을 설명함.
