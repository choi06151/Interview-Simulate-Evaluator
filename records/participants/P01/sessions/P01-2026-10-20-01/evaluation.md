## 우선 보완할 답변

1. **Unity 생명주기:** `Awake → OnEnable → Start`의 시작 순서와 활성/비활성 때의 콜백을 구분하고, `Update`, `FixedUpdate`, `LateUpdate`, `OnDestroy`의 역할을 정확히 설명해야 합니다. 현재 답변에는 함수 순서 오류와 업데이트 간격 혼동이 있습니다.
2. **C++ 스마트 포인터:** `unique_ptr`, `shared_ptr`, `weak_ptr`의 소유권과 수명 차이를 코드 사례로 설명할 수 있도록 준비해야 합니다.
3. **협업 충돌 사례:** 실제 아트/기획 요청 하나를 제시해 요청 의도, 기술 제약, 선택한 대안, 합의와 결과를 설명해야 합니다. 현재 답변은 올바른 일반 원칙을 말했지만 사례 근거가 없습니다.
4. **셰이더/AI 작업 증거:** 하나의 머티리얼 결과를 기준으로 노드/계산 흐름, AI가 만든 제안, 본인이 수정한 부분과 최종 확인 방법을 설명해야 합니다.

## 기술적으로 정확히 짚을 부분

- Unity의 시작 시점에서는 일반적으로 `Awake`가 먼저 호출되고, 활성 상태의 컴포넌트에는 `OnEnable`이 이어집니다. `Start`는 해당 스크립트가 처음 Update를 받기 전에 한 번 호출됩니다. 따라서 `Awake, Start, Enable, Update` 순서라는 답변은 부정확하며, 정확한 콜백 이름은 `OnEnable`입니다.
- `Update`와 `LateUpdate`는 활성 Behaviour에서 프레임마다 호출되며 `LateUpdate`는 Update 이후 실행됩니다. `FixedUpdate`는 물리 업데이트 루프의 고정 간격 호출입니다. 카메라 추적은 Update에서 대상 이동이 끝난 뒤 LateUpdate에서 따라가도록 구성할 수 있지만, LateUpdate가 고정된 물리 간격이라는 설명이나 일반적인 입력 처리를 LateUpdate에 둔다는 설명은 부정확합니다.
- `SetActive`로 `activeInHierarchy`가 실제로 바뀌면 연결된 스크립트에서 `OnEnable` 또는 `OnDisable`이 호출됩니다. `SetActive` 호출마다 항상 콜백이 발생한다고 일반화하면 안 됩니다.

근거: [Unity MonoBehaviour API](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/MonoBehaviour.html), [Unity 실행 순서 매뉴얼](https://docs.unity3d.com/6000.0/Documentation/Manual/execution-order.html), [Unity SetActive API](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/GameObject.SetActive.html).
