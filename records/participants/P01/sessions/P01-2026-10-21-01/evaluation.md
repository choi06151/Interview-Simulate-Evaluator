## 우선 보완할 답변

1. **스택·힙·GC 관계를 정확히 설명:** 함수 호출 프레임과 지역 값의 수명, 관리 힙의 객체 수명, GC가 도달 불가능한 객체를 회수하는 원리를 구분해야 합니다. 모든 변수/배열이 단순히 힙에 들어간다고 일반화하지 말고 값 형식·참조 형식 및 런타임 구현 맥락을 설명해야 합니다.
2. **풀 자료구조의 역할 분리:** `Dictionary<ObjectType, Queue<PooledObject>>` 같은 형태에서 Dictionary는 종류별 풀 조회, Queue는 풀 안의 재사용 대기 객체 관리라는 식으로 각 구조의 책임을 분리해 말해야 합니다. 풀 반환 시 상태 초기화, 용량 초과, 비활성 객체가 없을 때의 생성 정책도 포함해야 합니다.
3. **성능 주장을 측정과 연결:** GC나 Canvas 최적화 모두 먼저 CPU Profiler/Profiler를 통해 병목을 확인하고, 적용 전후 같은 조건의 프레임 시간·할당량·Canvas rebuild 비용을 비교해야 합니다. 풀링은 메모리를 더 점유할 수 있으므로 무조건 이득이라고 말하면 안 됩니다.
4. **단편화 답변 교정:** 고정 크기 page/frame 단위로 나누는 페이징은 메모리 외부 단편화를 줄이지만 마지막 페이지의 남는 공간 등 내부 단편화가 발생할 수 있습니다. 가변 크기 segment를 연속 공간에 배치하는 세그멘테이션은 외부 단편화가 발생할 수 있습니다.
5. **Delegate와 Event 구분:** Delegate는 호출 가능한 메서드 참조를 표현하는 타입입니다. Event는 Delegate 기반 알림에 구독/해제 API를 제공하고 선언 클래스 밖에서는 직접 발생시키지 못하도록 호출 권한을 제한합니다.

## 기술적으로 정확히 짚을 부분

- .NET의 관리 힙에서 GC가 회수하는 대상은 더 이상 사용되지 않는 관리 객체이며, GC 빈도와 소요 시간은 할당량 및 살아남는 객체량 등의 영향을 받습니다. 따라서 “생성·해제가 많으면 항상 느리다”로 끝내기보다 할당 패턴을 측정하고 적절한 재사용을 검증해야 합니다. [Microsoft Learn: Fundamentals of garbage collection](https://learn.microsoft.com/en-us/dotnet/standard/garbage-collection/fundamentals)
- Unity UI Canvas는 UI 요소 변경 시 Canvas를 다시 분석하고 메시/배칭을 갱신할 수 있습니다. 자주 갱신되는 요소와 정적 요소를 Canvas로 분리하면 변경 영향을 격리하는 데 도움이 되지만, 적절한 분리 단위는 프로파일링으로 확인해야 합니다. [Unity UI performance optimization tips](https://unity.com/how-to/unity-ui-optimization-tips)
- 일반적인 OS 메모리 관리 개념에서 페이징은 고정 크기 페이지 단위로 매핑되어 외부 단편화를 피하는 대신 내부 단편화가 발생할 수 있습니다. 세그멘테이션은 크기가 다른 세그먼트를 연속 배치해 외부 단편화가 생길 수 있습니다. [UC San Diego CSE 120: Memory Management, Segmentation, and Paging](https://cseweb.ucsd.edu/classes/sp16/cse120-a/applications/ln/lecture11and12.html)
- C#에서 Event는 Delegate에 기반하지만 구독자는 이벤트를 `+=`/`-=`로 구독·해제할 수 있고, 발생은 이벤트를 선언한 클래스가 담당합니다. [Microsoft Learn: Delegates vs. events](https://learn.microsoft.com/en-us/dotnet/csharp/distinguish-delegates-events)

## 총평

최재원 님은 풀링의 목적과 FIFO 대기 구조를 연결하고, 적·총알 풀에 Queue를 사용한 프로젝트 경험을 제시했습니다. 자주 바뀌는 UI와 정적 UI를 별도 Canvas로 나눈 사례도 실무적인 최적화 접근으로 확인됩니다. 반면 Dictionary와 Queue의 역할 관계를 명확히 설명하지 못했고, 페이징/세그멘테이션의 단편화 특성은 반대로 답했습니다. Delegate의 기본 정의는 일부 맞았지만 Event가 제공하는 호출 권한 제한과 구독 의미까지 구분하지 못했습니다. 텍스트 점수는 45점, 잠정 음성 전달 점수는 68점, 평균 최종 총점은 57점입니다. 음성 점수는 직접 청취가 아닌 로컬 ASR/시간 정보 기반이므로 신뢰도가 낮고 실제 음향 특성은 확인되지 않았습니다.
