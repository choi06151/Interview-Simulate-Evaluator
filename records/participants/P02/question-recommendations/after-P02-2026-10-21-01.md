# P02 3회차 이후 개인별 추천 질문

- 참가자: 김호준 (P02)
- 기준 세션: P02-2026-10-21-01
- 기준 루브릭: v2.0
- 목적: 이번 회차에서 답변이 없거나 개념 구분이 약했던 OOP/Unity 기초를 구체적으로 확인

## 1. 객체지향 네 가지 특징 구분

- 연결 평가: Q1 — 캡슐화·상속·다형성·추상화 (30/100)
- 난이도: 중
- 질문: 네 가지 특징을 각각 한 문장으로 정의하고, 게임의 무기 시스템에 적용한 예를 들어 주세요.
- 후속 질문:
  - 무기의 내부 탄약 수를 보호하려면 어떻게 캡슐화합니까?
  - 서로 다른 무기를 같은 발사 인터페이스로 다루면 어떤 특징인가요?
  - 무기 공통 개념만 선언하고 구현 세부를 감추는 것은 어떤 설계인가요?
- 좋은 답변 신호: 각 개념을 혼용하지 않고 같은 사례 안에서 어떤 설계 선택이 어느 특징인지 설명함.

## 2. 오버로딩과 오버라이딩

- 연결 평가: Q2 — 메서드 오버로딩/오버라이딩 차이 (0/100)
- 난이도: 기초
- 질문: `Damage(int amount)`와 `Damage(float amount)`를 같은 클래스에 선언하는 것과, 부모의 `virtual Attack()`을 자식에서 재정의하는 것은 각각 무엇이며 어떤 점이 다른가요?
- 후속 질문:
  - 컴파일 시점에 어떤 메서드를 선택하는지와 런타임 다형성은 각각 어느 쪽에서 보이나요?
  - 반환형만 바꾸면 오버로딩이 성립하나요?
  - 오버라이딩에 필요한 부모 메서드 조건은 무엇인가요?
- 좋은 답변 신호: 매개변수 시그니처 기반의 같은 타입 내 선언과 상속/virtual 기반 재정의를 구분함.

## 3. Unity 상속과 컴포넌트 조합

- 연결 평가: Q4 — 상속 기반 개발과 컴포넌트 기반 개발 (0/100)
- 난이도: 중
- 질문: 플레이어와 적이 공통 이동 기능을 사용하지만 입력 방식과 공격 방식은 다릅니다. 상속과 컴포넌트 조합으로 각각 설계하고 장단점을 비교해 주세요.
- 후속 질문:
  - 깊은 상속 계층이 변경을 어렵게 만드는 경우는 언제인가요?
  - 컴포넌트 간 참조가 복잡해지면 어떻게 관리하나요?
  - 어떤 조건에서 상속을 선택하고 어떤 조건에서 조합을 선택하나요?
- 좋은 답변 신호: 실제 요구에 맞춰 중복/결합/확장성을 비교하고, 한 방식을 무조건 정답으로 취급하지 않음.

## 4. Unity 직렬화와 Inspector

- 연결 평가: Q6 — 직렬화 목적 (40/100)
- 난이도: 중
- 질문: `MonoBehaviour`의 `[SerializeField] private int damage` 필드가 Inspector에 표시되고 씬을 다시 열어도 값이 유지되는 과정을 직렬화 관점에서 설명해 주세요.
- 후속 질문:
  - Unity가 씬/프리팹에서 저장하고 복원하는 데이터는 무엇인가요?
  - 프로퍼티와 필드의 직렬화 동작은 어떻게 다릅니까?
  - 플레이어 진행 데이터를 저장하는 런타임 세이브와 Inspector 직렬화는 같은 기능인가요?
- 좋은 답변 신호: 저장 가능한 필드 표현과 복원 과정을 설명하고 에디터 데이터/씬 데이터와 플레이어 세이브 목적을 구분함.

## 5. deltaTime과 Rigidbody 업데이트 위치

- 연결 평가: Q3 — deltaTime을 곱하는 이유 (70/100)
- 난이도: 중
- 질문: 초당 5유닛 속도로 움직이는 캐릭터를 30FPS와 120FPS에서 같은 속도로 이동시키려면 어떤 계산을 하며, Rigidbody 이동은 어느 업데이트 단계에서 처리하나요?
- 후속 질문:
  - deltaTime을 곱하지 않을 때 프레임률에 따라 결과가 어떻게 달라지나요?
  - `FixedUpdate`와 `Update`에서 deltaTime 값은 어떻게 해석되나요?
  - 입력은 Update에서 받고 물리 적용은 FixedUpdate에서 하려면 값을 어떻게 전달하나요?
- 좋은 답변 신호: 속도×경과 시간의 단위 관계를 설명하고 프레임 기반 이동과 고정 시간 물리 갱신을 구분함.
