# 김호준 5회차 이후 개인별 추천 질문

- 참가자: 김호준 (P02)
- 기준 세션: [P02-2026-10-27-01](../sessions/P02-2026-10-27-01/evaluation.md)
- 기준 루브릭: 텍스트 v2.0
- 목적: Observer와 C# 이벤트 경계, 기술 제약 협의, Singleton 대안, SOLID 전이를 구체 사례로 확인

## 1. Observer, Action, event, UnityEvent

- 연결 평가: Q1 — 이벤트 패턴과 구독 해제 (40/100)
- 난이도: 중
- 질문: 체력 변경을 UI와 사운드가 구독해 반응하도록 설계할 때 Observer의 발행자·구독자 관계를 설명하고, Action 필드, C# event, UnityEvent의 차이를 비교해 주세요.
- 후속 질문:
  - 각 방식에서 누가 알림을 호출할 수 있나요?
  - UnityEvent의 Inspector 연결/직렬화는 어떤 상황에 유용하고 어떤 비용이 있나요?
  - Unity 오브젝트가 비활성화되거나 파괴될 때 구독과 해제를 어느 생명주기에 둘까요?
- 좋은 답변 신호: 옵저버 알림 관계를 먼저 설명하고, event도 delegate 기반임을 구분하며 발행 권한과 UnityEvent의 Inspector listener를 정확히 설명함.

## 2. 비개발 직군 요청의 범위 조정

- 연결 평가: Q2 — 구현 제약과 일정 조율 (40/100)
- 난이도: 중
- 질문: 아티스트가 마감 1주 전에 성능 비용이 큰 실시간 후처리 효과를 요청했습니다. 요구 목적을 확인하고 일정·성능·품질을 어떻게 조율하겠습니까?
- 후속 질문:
  - 필수 요구와 선택 요구를 어떤 질문으로 나누나요?
  - 구현이 어려울 때 제시할 축소안 또는 대체안 두 가지는 무엇인가요?
  - 결정, 위험, 테스트 기준을 누구와 어떻게 공유하나요?
- 좋은 답변 신호: 요청 의도 확인, 비용/위험 근거, 대안 비교, 결정권자 합의, 플레이 테스트 기준을 구체적으로 제시함.

## 3. Singleton 과용과 대안

- 연결 평가: Q3 — Singleton 장단점 및 사용처 (45/100)
- 난이도: 중
- 질문: 게임 매니저와 사운드 매니저가 모두 Singleton인 프로젝트에서 씬 전환 후 중복 생성, 테스트 격리 실패, 숨은 의존성이 생겼습니다. 무엇을 Singleton으로 유지하고 무엇을 대체할까요?
- 후속 질문:
  - 씬 범위 서비스와 앱 전체 서비스의 수명 차이를 어떻게 표현하나요?
  - 생성자 주입/명시적 참조가 전역 접근보다 나은 경우는 언제인가요?
  - 중복 인스턴스 방지와 테스트 가능한 구조를 어떻게 검증하나요?
- 좋은 답변 신호: “하나뿐임”과 “전역 접근”을 별도 요구로 보고 생명주기·결합도·테스트 비용을 근거로 선택함.

## 4. SRP와 DIP 적용

- 연결 평가: Q4 — SOLID 원칙 설명 (45/100)
- 난이도: 중
- 질문: PlayerController가 입력 읽기, 이동, 체력, UI 표시를 모두 처리할 때 SRP를 적용해 책임을 나누고, 입력 장치와 플레이어 이동 구현이 직접 결합되지 않도록 DIP를 적용해 주세요.
- 후속 질문:
  - 인터페이스를 어느 계층에 두고 누가 구현하나요?
  - 변경 이유가 서로 다른 클래스 책임은 어떻게 구분하나요?
  - 분리 뒤 단위 테스트에서 어떤 동작을 검증하나요?
- 좋은 답변 신호: SRP와 DIP의 목적을 구분하고, 과도한 분해를 피하면서 의존성 방향·대체 구현·검증 방법을 설명함.
