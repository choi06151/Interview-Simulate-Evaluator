## 1. Git 실수 복구와 재발 방지

- 연결 평가: Q1 — 본인 실수로 인한 팀 프로젝트 지연 (60/100)
- 난이도: 중
- 질문: 저장소 관리 문제로 일정이 지연된 당시 어떤 작업이 영향을 받았고, 본인이 어떤 순서로 복구하고 팀에 공유했는지 설명해 주세요. 이후 같은 문제가 반복되지 않도록 무엇을 바꿨습니까?
- 후속 질문:
  - 커밋/브랜치/병합 중 구체적으로 어떤 문제가 있었나요?
  - 충돌이나 작업 손실을 줄이는 팀 규칙은 무엇인가요?
  - 문제가 재발했는지, 재발을 어떻게 확인했나요?
- 좋은 답변 신호: 책임을 인정하면서 영향 범위, 복구, 조기 공유, 구체적인 예방 절차를 설명하고 개인의 주의에만 의존하지 않음.

## 2. Unreal 모션 매칭 구현 설명

- 연결 평가: Q2 — 자신 있는 분야와 대표 사례 (50/100)
- 난이도: 중상
- 질문: 모션 매칭 프로젝트에서 본인이 구현하거나 조정한 부분을 구체적으로 설명해 주세요. 입력 데이터부터 애니메이션 선택과 캐릭터 적용까지 어떤 흐름으로 동작했나요?
- 후속 질문:
  - 데이터 준비나 검색 기준은 어떻게 구성했나요?
  - 원하는 애니메이션이 선택되지 않는 문제를 어떻게 진단했나요?
  - 본인 기여를 증명할 수 있는 코드, 툴, 결과물은 무엇인가요?
- 좋은 답변 신호: 사용 경험과 본인 구현을 구분하고, 데이터 흐름·기술 선택·문제 해결·결과를 구체적으로 설명함.

## 3. Unity 관리 힙 할당과 GC 프로파일링

- 연결 평가: Q3 — GC 프레임 드랍 최적화 (30/100)
- 난이도: 중
- 질문: Update에서 매 프레임 문자열을 만들고 임시 리스트를 생성하는 코드가 있습니다. GC 부담을 확인하고 줄이는 방법을 설명해 주세요.
- 후속 질문:
  - Profiler에서 어떤 지표와 프레임을 확인하나요?
  - 리스트를 재사용할 때 초기화와 최대 용량은 어떻게 관리하나요?
  - 객체 풀을 적용할 때 생명주기와 풀 크기는 어떻게 결정하나요?
- 좋은 답변 신호: GC.Alloc 등으로 할당 위치를 측정하고, 원인별로 재사용·캐싱·풀링을 적용한 뒤 같은 조건에서 개선을 검증함.

## 4. CPU에서 GPU까지의 렌더링 흐름

- 연결 평가: Q4·Q5 — 셰이더 지식 수준과 렌더링 과정 (40/100, 20/100)
- 난이도: 중
- 질문: 게임 오브젝트 하나가 화면에 그려지는 과정을 CPU 측 준비부터 GPU 처리 결과까지 큰 단계로 설명해 주세요.
- 후속 질문:
  - 정점 셰이더와 픽셀/프래그먼트 셰이더는 각각 어떤 입력을 처리하나요?
  - 드로우 콜이 많을 때 CPU 비용과 GPU 비용은 어떻게 구분해 확인하나요?
  - 직접 작성하거나 수정한 셰이더에서 어떤 값을 입력받고 어떤 결과를 출력했나요?
- 좋은 답변 신호: CPU의 렌더 명령/리소스 준비와 GPU의 그래픽 파이프라인을 구분하며, 직접 경험과 개념 설명을 구별함.

## 5. ScriptableObject 데이터와 런타임 상태 분리

- 연결 평가: Q6 — 포션 데이터 에셋 설계 (70/100)
- 난이도: 중
- 질문: 20종 포션을 ScriptableObject로 설계했다면 에셋 필드와 실제 게임 중 변하는 포션 상태를 어떻게 나눴나요? 기획자가 데이터를 수정했을 때 오류를 어떻게 예방했습니까?
- 후속 질문:
  - 포션 효과가 서로 달라도 데이터 구조를 어떻게 확장했나요?
  - 에셋 누락이나 잘못된 값은 언제 검증했나요?
  - 빌드 후 플레이어가 획득한 포션 수량은 어디에 저장했나요?
- 좋은 답변 신호: 변경하지 않는 정의 데이터와 세션/플레이어별 런타임 상태를 구분하고, 확장성·검증·저장 경계를 설명함.
