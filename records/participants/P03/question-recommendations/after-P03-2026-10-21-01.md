## 1. C# 값 형식·참조 형식과 매개변수 전달

- 연결 평가: Q1·Q2 — 값/참조 형식과 struct/class (20/100, 30/100)
- 난이도: 중
- 질문: struct와 class 인스턴스를 메서드에 기본 방식으로 전달한 뒤, 메서드 안에서 멤버 값을 바꾸는 경우와 매개변수 자체를 새 값/객체로 재할당하는 경우 호출자에서 어떤 결과가 보이는지 설명해 주세요.
- 후속 질문:
  - `ref`를 붙이면 어떤 동작이 달라지나요?
  - struct와 class 모두 메서드와 프로퍼티를 가질 수 있나요?
  - 참조 형식 변수가 객체를 저장하는 것과 참조 자체를 전달하는 것은 어떻게 다릅니까?
- 좋은 답변 신호: 타입 분류와 전달 방식을 별개 축으로 설명하고, 복사되는 것이 값인지 참조값인지 코드 예제로 추적함.

## 2. 배열과 연결 리스트의 복잡도 조건

- 연결 평가: Q4 — 배열/연결 리스트와 시간 복잡도 (30/100)
- 난이도: 중
- 질문: 배열과 연결 리스트에서 인덱스 접근, 값 검색, 중간 삽입·삭제의 시간 복잡도를 설명하고, 각 연산의 전제 조건을 말해 주세요.
- 후속 질문:
  - 연결 리스트에서 삽입할 노드 위치를 이미 알고 있으면 왜 O(1)이 될 수 있나요?
  - 그 위치를 먼저 검색해야 한다면 전체 연산은 어떻게 되나요?
  - 배열 중간에 원소를 삽입하면 어떤 데이터 이동이 발생하나요?
- 좋은 답변 신호: 배열 인덱스 접근 O(1)과 값 검색 O(n)을 구분하고 연결 리스트의 O(1) 삽입/삭제가 위치를 알고 있을 때라는 조건을 설명함.

## 3. A* 휴리스틱과 다익스트라 비교

- 연결 평가: Q3 — 경로 탐색 알고리즘과 프로젝트 적용 (50/100)
- 난이도: 중상
- 질문: 같은 가중치 그래프에서 다익스트라와 A*가 노드를 어떤 우선순위로 확장하는지 `g(n)`, `h(n)`, `f(n)`을 사용해 설명해 주세요.
- 후속 질문:
  - 휴리스틱이 0이면 A*는 어떻게 동작하나요?
  - 휴리스틱이 실제 남은 비용을 과대평가하면 최적 경로 보장에 어떤 영향이 있나요?
  - 본인 프로젝트의 그리드에 맨해튼 거리와 유클리드 거리 중 무엇을 고르고, 어떤 조건으로 검증하겠습니까?
- 좋은 답변 신호: 다익스트라가 누적 비용을 기준으로 탐색하고 A*는 휴리스틱 추정치를 더해 목표 방향을 안내함을 설명하며, 프로젝트의 그래프/비용/결과를 구체화함.

## 4. 비동기와 멀티스레딩 구분

- 연결 평가: Q5 — 동기 처리와 비동기 처리 (20/100)
- 난이도: 중
- 질문: 파일 읽기처럼 I/O 대기 작업과 큰 행렬 계산처럼 CPU 작업을 각각 처리한다고 할 때, 동기·비동기·멀티스레딩을 어떻게 선택하고 구분하겠습니까?
- 후속 질문:
  - `async` 메서드가 호출될 때마다 새 스레드가 생기나요?
  - 비동기 I/O가 UI 응답성을 높이는 이유는 무엇인가요?
  - CPU 작업을 백그라운드로 보내려면 어떤 추가 선택이 필요할까요?
- 좋은 답변 신호: 비동기를 대기 중 호출 흐름을 막지 않는 모델로 설명하고, 이를 별도 스레드 실행과 동일시하지 않음.

## 5. 경쟁 상태를 동기화로 해결하는 방법

- 연결 평가: Q6·Q7 — 프로세스/스레드와 멀티스레드 동기화 (60/100, 60/100)
- 난이도: 중상
- 질문: 두 작업 스레드가 같은 인벤토리 수량을 동시에 갱신해 아이템 수가 틀어지는 버그가 있습니다. 경쟁 상태가 생기는 순서를 설명하고 안전하게 고치는 방법을 제안해 주세요.
- 후속 질문:
  - 임계 구역은 어디이며 락을 어느 범위에 둡니까?
  - 락 범위가 너무 넓으면 어떤 성능 문제가 생기나요?
  - 두 락을 서로 다른 순서로 획득하면 어떤 문제가 생길 수 있나요?
- 좋은 답변 신호: 읽기-수정-쓰기의 원자성 문제를 설명하고 적절한 동기화 범위, 경합, 데드락 위험을 함께 고려함.
