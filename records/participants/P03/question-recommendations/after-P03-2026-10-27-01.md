# 김문규 5회차 이후 개인별 추천 질문

- 참가자: 김문규 (P03)
- 기준 세션: [P03-2026-10-27-01](../sessions/P03-2026-10-27-01/evaluation.md)
- 기준 루브릭: 텍스트 v2.0
- 정정 반영: 2026-10-29 정정 전사 재평가
- 목적: 커맨드 패턴 기초, 인벤토리 동시성, 몬스터 확장 설계, ScriptableObject의 런타임 상태 경계를 연습

## 1. 커맨드 패턴의 기본 구조

- 연결 평가: Q1 — 커맨드 패턴 설명 (0/100, 답변 보류)
- 난이도: 기초
- 질문: 게임에서 버튼 입력으로 캐릭터가 공격하도록 할 때, 커맨드 패턴을 적용하면 어떤 객체가 생기고 각각 무슨 책임을 맡나요?
- 후속 질문:
  - 입력 처리와 공격 실행은 어떻게 분리되나요?
  - 명령 객체가 실행 대상과 동작 정보를 어떻게 전달하나요?
- 좋은 답변 신호: 호출자와 실행자를 분리하는 구조를 설명하고, 입력 이벤트에서 명령 실행까지 구체적인 흐름을 듦.

## 2. 인벤토리 수량 변경과 동시성

- 연결 평가: Q2–Q3 — 인벤토리 설계와 UI 갱신·병렬 처리 (20/100)
- 난이도: 중
- 질문: 두 작업이 동시에 같은 인벤토리 아이템 수량을 바꾸고 UI도 갱신해야 한다면, 데이터 일관성과 화면 반영을 어떻게 보장하겠습니까?
- 후속 질문:
  - 옵저버 패턴은 이 흐름에서 어떤 책임을 맡고, 어떤 문제는 해결하지 못하나요?
  - 잠금이나 단일 스레드 소유 등 선택한 동기화 방식이 필요한 이유는 무엇인가요?
  - 수량이 중복 차감되거나 UI에 두 번 반영되지 않는지 어떻게 검증하나요?
- 좋은 답변 신호: 데이터 변경을 직렬화·동기화하는 방식과 변경 알림을 구분하고, UI 구독 수명과 검증 사례를 설명함.

## 3. 조합 가능한 몬스터 확장

- 연결 평가: Q4–Q6 — 몬스터 확장과 상속·컴포지션 선택 (35/100)
- 난이도: 중
- 질문: 이동 방식과 공격 능력이 서로 다른 몬스터를 추가할 때, 상속과 컴포지션을 어떤 기준으로 선택하고 생성 구조를 어떻게 구성하겠습니까?
- 후속 질문:
  - 기존 몬스터 코드를 고치지 않고 새 종류를 추가하려면 어떤 데이터를 분리할 수 있나요?
  - 팩토리는 생성 과정에서 어떤 책임을 맡나요?
  - 새 조합이 늘어날 때 중복 코드나 잘못된 설정을 어떻게 확인하나요?
- 좋은 답변 신호: 공통 상태·행동과 조합형 능력의 경계를 설명하고, 상속·컴포지션 선택 이유와 추가 시 변경 범위를 예시로 듦.

## 4. ScriptableObject 설정과 플레이 중 상태

- 연결 평가: Q7–Q8 — ScriptableObject 활용, 런타임 주의점과 사용 경험 (30/100)
- 난이도: 중
- 질문: ScriptableObject에 무기의 기본 공격력을 저장하고, 플레이 중 강화로 플레이어마다 공격력이 달라질 때 데이터 구조를 어떻게 나누겠습니까?
- 후속 질문:
  - 두 플레이어가 같은 무기를 쓰면서 서로 다른 강화값을 가지면 강화값은 어디에 저장하나요?
  - 플레이 중 공유 에셋을 직접 바꾸면 어떤 문제가 생길 수 있나요?
  - 변경된 상태를 저장하고 검증하는 책임은 어느 계층에 둘까요?
- 좋은 답변 신호: 공유 에셋을 기본 설정으로 사용하고 플레이어별 런타임 상태를 분리하며, 저장·검증 경계를 설명함.
