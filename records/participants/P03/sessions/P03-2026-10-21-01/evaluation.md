## 우선 보완할 답변

1. **값 형식/참조 형식과 매개변수 전달 분리:** 값 형식은 인스턴스 값이 변수에 담기고, 참조 형식 변수에는 객체를 가리키는 참조가 담깁니다. C# 매개변수는 기본적으로 값으로 전달됩니다. 참조 형식 인자를 값으로 넘겨도 참조의 복사본이 전달되어 같은 객체를 가리킬 수 있으므로 이를 “참조로 전달”과 혼동하지 않아야 합니다.
2. **구조체/클래스 선택 근거:** 두 타입 모두 데이터와 메서드를 가질 수 있습니다. struct는 값 형식이고 class는 참조 형식이라는 점, 복사 동작·변경 가능성·크기/수명·상속 등 선택에 영향을 주는 특성을 중심으로 비교해야 합니다.
3. **복잡도 설명에서 조건 명시:** 배열 인덱스 접근 O(1)과 값 검색 O(n)을 구분합니다. 연결 리스트의 삽입/삭제 O(1)은 위치 노드를 이미 알고 있을 때 기준이고, 위치를 찾는 비용은 별도입니다.
4. **비동기와 멀티스레딩 분리:** 비동기는 작업 완료를 기다리는 동안 호출 흐름을 막지 않게 조정하는 모델이며 반드시 새 스레드를 뜻하지 않습니다. CPU 작업 병렬화가 필요할 때는 스레드/스레드풀을 별도로 고려합니다.
5. **동기화 기법을 코드 흐름으로 구체화:** 공유 카운터나 풀 자료구조 같은 임계 구역을 예로 들고, 어떤 락/세마포어를 어떤 범위로 적용하는지 설명해야 합니다. 락 범위가 길어질 때의 경합이나 데드락 가능성도 검토해야 합니다.

## 기술적으로 정확히 짚을 부분

- C#에서는 기본적으로 인자를 값으로 전달합니다. struct를 넘기면 값의 복사본, class를 넘기면 참조의 복사본을 전달합니다. 두 변수가 같은 객체를 참조하면 객체 내부 변경은 공유되지만, 매개변수 참조를 다른 객체로 재할당하는 것이 호출자 변수의 재할당을 뜻하지는 않습니다. [Microsoft Learn: Method parameters and modifiers](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/classes-and-structs/passing-reference-type-parameters)
- 배열의 인덱스 접근은 O(1)이지만 임의의 값을 찾는 선형 검색은 O(n)입니다. 연결 리스트도 삽입/삭제 위치를 이미 알고 있으면 O(1)이 가능하나, 먼저 해당 노드를 검색하면 O(n)입니다.
- A*는 경로 비용 `g(n)`에 목표까지의 휴리스틱 추정치 `h(n)`를 더해 탐색 우선순위를 정합니다. 다익스트라는 목표 방향 휴리스틱 없이 누적 비용이 낮은 노드부터 확장하며, 비음수 간선 가중치 조건에서 최단 경로를 구합니다. 적절한 휴리스틱의 admissibility/consistency는 최적 경로 보장과 관련됩니다. [Cornell CS 312: A* Search](https://www.cs.cornell.edu/courses/cs312/2007sp/recitations/rec26.html)
- `async`/`await`를 사용한다고 메서드가 자동으로 백그라운드 스레드에서 실행되는 것은 아닙니다. 특히 비동기 I/O는 별도 스레드 없이 대기할 수 있습니다. [Microsoft Learn: Common async/await bugs](https://learn.microsoft.com/en-us/dotnet/standard/asynchronous-programming-patterns/common-async-bugs)
- 프로세스는 주소 공간과 실행 자원을 제공하고 스레드는 스케줄되어 실행되는 단위입니다. 같은 프로세스의 스레드들은 주소 공간/자원을 공유하며 각 스레드는 별도 실행 상태와 스택을 가집니다. 공유 데이터 접근을 동기화하지 않으면 경쟁 상태가 생길 수 있습니다. [Microsoft Learn: About Processes and Threads](https://learn.microsoft.com/en-us/windows/desktop/ProcThread/about-processes-and-threads), [Microsoft Learn: Threads and threading](https://learn.microsoft.com/en-us/dotnet/standard/threading/threads-and-threading)

## 총평

김문규 님은 프로세스와 스레드의 기본 관계, 스레드 공유 자원으로 인한 경쟁 상태, A*에서 휴리스틱을 사용한다는 핵심을 알고 있었습니다. 다만 C# 값/참조 형식과 매개변수 전달 방식을 혼동했고, struct/class의 선택 기준도 정확하지 않았습니다. 배열/연결 리스트의 탐색 및 삽입·삭제 복잡도를 조건 없이 잘못 제시했으며, 비동기 실행을 별도 시간 로직이나 스레드 실행과 연결했습니다. 기본 용어를 암기하는 데서 멈추지 않고, 작은 코드 예제와 시간 복잡도 조건을 함께 설명하는 연습이 필요합니다. 텍스트 점수는 39점, 잠정 음성 전달 점수는 60점, 평균 최종 총점은 50점입니다. 음성 점수는 직접 청취가 아닌 로컬 ASR/시간 정보 기반이므로 신뢰도가 낮고 실제 음향 특성은 확인되지 않았습니다.
