## 우선 보완할 답변

1. **페이지 폴트 처리 순서:** 페이지 폴트는 “주소가 존재하지 않음”만을 뜻하지 않습니다. 페이지 테이블 상태를 확인하고 접근이 유효한지 판별한 뒤, 유효한 페이지라면 메모리에 매핑/적재하고 테이블을 갱신해 원래 명령을 재개하는 흐름을 그림으로 설명합니다. 디스크 접근이 필요한 hard fault와 메모리에서 해결되는 soft fault도 구분합니다.
2. **스케줄링 알고리즘 용어 정리:** FCFS, SJF/SRTF, Round Robin을 대기 시간·응답성·공정성 기준으로 비교합니다. “가장 최근에 들어온 작업”은 SJF 정의가 아닙니다. 응답성이 중요할 때 RR이 왜 유리할 수 있는지, time quantum이 너무 크거나 작을 때의 trade-off도 설명합니다.
3. **팩토리의 목적과 단점 구체화:** 생성 코드를 중앙화해 호출자가 구체 생성 타입/초기화 세부 사항에 덜 의존하도록 하는 점을 설명합니다. 단점은 요구 변화에 따라 팩토리 분기/타입 등록이 커지거나 단순 생성에 불필요한 추상화가 될 수 있다는 식으로 구체화합니다.
4. **재귀 종료와 스택:** 기저 조건은 재귀가 멈추는 종료 조건이며, 각 재귀 호출은 반환 지점과 지역 상태를 보관하는 호출 프레임을 쌓습니다. 종료가 없거나 깊이가 너무 크면 스택이 소진됩니다. 작은 입력 예로 호출 깊이를 추적합니다.

## 기술적으로 정확히 짚을 부분

- 가상 주소 공간은 프로세스가 사용하는 주소 추상화이며 물리 메모리에 상주하는 페이지가 일부일 수 있습니다. 페이지 폴트 핸들러는 페이지를 해결할 수 있는지 판정하며, hard fault는 backing store 읽기가 필요하지만 soft fault는 디스크 접근 없이 해결될 수도 있습니다. [Microsoft: Working Set](https://learn.microsoft.com/en-us/windows/win32/memory/working-set), [Microsoft: Virtual Address Space and Physical Storage](https://learn.microsoft.com/en-us/windows/win32/memory/virtual-address-space-and-physical-storage)
- 스케줄링은 처리량, 지연/응답시간, 공정성 등 서로 다른 목표를 절충합니다. SJF는 평균 대기 시간을 줄이는 데 유리할 수 있지만, 인터랙티브 응답성은 RR의 작은 시간 할당량 같은 특성으로 다루며 만능 알고리즘은 없습니다. [Illinois CS 341: Scheduling](https://cs341.cs.illinois.edu/coursebook/Scheduling), [Stanford CS 111: Scheduling](https://web.stanford.edu/~ouster/cs111-spring24/lectures/scheduling/)
- Factory 계열은 객체 생성을 호출부에서 분리/캡슐화하고 구체 생성 타입을 호출자가 직접 알 필요를 줄이는 생성 패턴입니다. [Microsoft Learn: Design Patterns—Factories](https://learn.microsoft.com/en-us/shows/visual-studio-toolbox/design-patterns-factories)
- 재귀 호출이 깊거나 종료되지 않아 실행 스택에 중첩 호출이 지나치게 쌓이면 StackOverflowException이 발생할 수 있습니다. [Microsoft Learn: Debugging StackOverflow errors](https://learn.microsoft.com/en-us/dotnet/core/diagnostics/debug-stackoverflow)
