# 고정 평가 루브릭 v2.0 — 질문 단위 엄격 채점

## 평가 단위와 텍스트 점수

- 점수의 단위는 역량 항목이 아니라 면접에서 실제로 묻고 답한 **질문 단위**다.
- 하나의 주제를 묻는 주 질문과 그 답을 구체화하는 후속 질문은 한 질문 단위로 묶는다. 주제나 평가하려는 행동이 독립적으로 달라지면 별도 질문 단위로 나눈다. 인사, 진행 안내, 같은 내용을 되묻는 말은 채점하지 않는다.
- 각 질문 단위에 `Q1`, `Q2`처럼 번호를 붙이고, 답변 점수 `0–100`과 평가 근거를 적는다. 기술/협업 등 역량 태그는 기록과 범위 설명에만 사용하며 별도 항목 점수를 합산하지 않는다.
- 텍스트 점수는 채점 가능한 질문 단위 점수들의 **단순 평균**을 정수 반올림해 `100점 만점`으로 표시한다. 질문별 가중치는 두지 않는다. 이는 텍스트 답변 내용 점수이며, 세션 최종 총점은 음성 점수가 있을 때 텍스트 점수와 음성 점수의 평균으로 산출한다. 서로 다른 질문 구성을 가진 면접 간 비교는 제한될 수 있다.
- 질문을 받았지만 답변을 넘기거나 답하지 않았으면 해당 질문 점수는 0점이다. 그 주제를 면접에서 묻지 않았다면 0점으로 만들지 않고 범위 밖으로 기록한다.
- 질문이 지나치게 모호하거나 답할 기회가 없었던 상황이면 후보자 점수에 불리하게 반영하지 말고 `채점 제외` 사유를 남긴다.

## 질문별 점수 앵커

질문의 범위와 난이도에 맞춰 답변의 정확성, 직접성, 근거, 설명 깊이, 적용/검증을 평가한다. 아래 구간은 기준점이며, 구간 사이 점수는 보수적으로 부여하고 이유를 적는다.

| 점수 | 기준 |
|---:|---|
| 0 | 답변하지 않음, 질문을 넘김, 또는 핵심 결론이 틀려 질문에 답하지 못함. |
| 1–20 | 질문과 관련된 용어·주장만 제시하거나 답변이 매우 피상적임. 핵심 원리나 행동 근거가 없음. |
| 21–40 | 일부 관련 내용은 맞지만 핵심 메커니즘, 구체적 경험, 결정 근거에 큰 공백이 있음. |
| 41–60 | 질문의 핵심에 기본적으로 답함. 다만 설명의 정확성/깊이, 사례의 구체성, 검증 또는 결과 중 중요한 요소가 빠짐. |
| 61–80 | 질문에 정확하고 구조적으로 답하며, 적절한 구체 사례나 이유, 적용 방법을 제시함. 주요 한계나 후속 검증도 다룸. |
| 81–100 | 질문 범위에서 매우 정확하고 깊이 있음. 독립적 추론, 구체 근거, 대안/경계 조건, 검증 또는 결과와 회고가 일관되게 드러남. 만점은 드물게 부여함. |

## 엄격 채점 규칙

- 정답 키워드, 경력 연수, 자신감, 말의 양으로 점수를 주지 않는다. 실제 답변 내용과 질문이 요구한 수준만 평가한다.
- 기술 질문은 핵심 개념의 정확성, 작동 원리, 적용 맥락, 트레이드오프, 검증 근거를 본다. 결론만 맞고 이유를 설명하지 못하면 높은 점수를 주지 않는다.
- 디버깅/성능 질문은 재현, 측정, 가설, 검증 과정을 실제로 설명하는지 본다. “확인해 보겠다”, “최적화하겠다”만으로 높은 점수를 주지 않는다.
- 행동/협업 질문은 구체적인 상황, 본인의 행동, 판단 이유, 결과와 회고를 본다. “대화로 해결하겠다” 또는 “열심히 배우겠다” 같은 의지 표명만으로 높은 점수를 주지 않는다.
- 짧은 사실 확인형 질문은 그 질문이 요구한 범위 내에서 평가한다. 단답이 질문에 충분히 정확하게 답했다면 단순히 답변이 짧다는 이유로 감점하지 않는다. 다만 이어진 개방형 후속 질문에 답하지 않았다면 해당 후속 요구도 같은 질문 단위 점수에 반영한다.
- `모르겠습니다`라고 정확히 밝히는 것은 허위 설명보다 낫지만, 기술 지식이나 행동 역량의 증거를 대신하지 않는다. 면접관이 답의 핵심을 알려준 뒤 나온 응답은 독립 답변과 구분하며 높은 점수를 제한한다.
- 말투, 속도, 억양, 유창성, 성격·호감도, 학력·나이·출신은 평가하지 않는다. 설명이 이해되지 않을 정도로 불명확한 경우에만 해당 질문에서 전달된 근거가 제한된 점을 설명한다.
- 행동 질문으로 성격·인성을 진단하지 않는다. 협업 갈등에서는 쟁점 파악, 상대 관점 청취, 기준에 따른 조율, 의사결정/에스컬레이션, 결과 확인을 관찰한다.
- 질문의 난이도, 힌트, 후속 질문, 불명확성을 근거 옆에 기록한다. 동일한 실수를 서로 다른 질문에서 반복하지 않는 한 근거 없는 중복 감점을 하지 않는다.
- 질문별 점수는 면접 범위 안의 답변 평가다. 총점만으로 채용 합격/불합격을 판정하지 않는다.

## 역량 태그와 범위

각 질문에는 필요하면 다음 태그를 하나 이상 붙인다. 태그별 점수는 산출하지 않는다.

| 태그 | 관찰 영역 예시 |
|---|---|
| C++/런타임 | 객체 수명, 메모리/소유권, 자료구조, 동시성 |
| 엔진/클라이언트 구조 | 프레임 루프, 오브젝트/컴포넌트, 이벤트, 모듈 경계 |
| 게임플레이 구현 | 입력, 캐릭터, 카메라, 전투, 상태 관리 |
| 그래픽스/물리/애니메이션 | 렌더링 흐름, 셰이더, 시뮬레이션, 연동 |
| 성능/메모리 | 측정, 병목, 프레임 시간, 할당/메모리 비용 |
| 디버깅/문제 해결 | 재현, 가설, 관찰, 수정, 회귀 검증 |
| 네트워크/플랫폼/빌드 | 클라이언트 권한, 플랫폼 차이, 빌드/배포 |
| 기술 소통 | 질문 의도 파악, 근거와 트레이드오프 설명 |
| 협업/업무 상황 | 의견 충돌, 피드백, 실패, 우선순위, 모호한 요구 |
| 동기/경험 | 지원 동기, 프로젝트 경험 및 역할 |

대화에서 나온 질문만 태그를 달고, 다루지 않은 영역은 `평가하지 않음`으로 요약한다. 총점의 신뢰도는 질문 수, 기술/행동 질문 범위, 난이도와 후속 검증 정도를 근거로 표시한다.

## 회차 간 비교

- 질문 단위 총점 비교는 직무 레벨과 질문 난이도/범위가 비슷할 때만 참고한다. 질문 수가 많거나 주제 구성이 다른 세션의 평균을 성장으로 단정하지 않는다.
- 성장 판단은 같은 역량 태그의 질문과 비슷한 난이도에서 답변 근거가 개선됐는지 확인한다. 가능하면 같은 질문을 그대로 반복하기보다 동등 난이도의 변형 질문으로 전이를 확인한다.
- 루브릭 v1.x의 항목별 점수는 v2.0 질문별 점수와 직접 비교하지 않는다. v2.0 기준으로 이전 transcript를 다시 채점한 뒤 비교한다.
